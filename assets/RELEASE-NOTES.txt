1.0.0-dev.1
===========

PetToys.BigDecimal.Core

- The N format specifier now honours the whole of the culture's group size list,
  as System.Decimal does. A culture that groups three digits and then two is
  grouped that way rather than uniformly in threes, a size list ending in zero
  stops grouping where it says to, and a culture that asks for no grouping gets
  none rather than groups of three. Output changes under those cultures.
- Formatting with N no longer allocates. It cost 64 bytes on every call, in the
  char and the UTF-8 overload alike, and was the last exception to the package's
  zero-allocation guarantee.
- Conversion from double and float now takes the shortest decimal form that
  round-trips, where it took 15 and 7 significant digits before. A double or a
  float the type can hold comes back unchanged, so (double)(BigDecimal)value
  returns value. Values that used to arrive rounded now arrive with more digits.
- The generic conversions honour their own contracts. CreateChecked throws where
  the value does not fit, CreateSaturating and CreateTruncating clamp to the
  target's range, and all three ask the other type to convert itself before
  giving up with NotSupportedException instead of silently returning zero. Half,
  NFloat and char are recognised in both directions.
- CreateChecked, CreateSaturating and CreateTruncating are callable on the type
  itself, as they are on every numeric type in the base class library.
- New: Precision, the number of decimal digits in the unscaled mantissa, so that
  a caller can decide whether a value fits a column before writing it.
- Converting out of the type no longer boxes, and TryParse no longer allocates
  an exception for a value too large to parse.
- Formatting now matches System.Decimal across its whole surface. The C, P and R
  specifiers are accepted where they threw, custom numeric format strings are
  supported, and G with a precision counts significant digits and switches to
  scientific notation instead of ignoring the precision.
- N lays a negative value out by the culture's NumberNegativePattern. A culture
  that writes (1,234.5) got -1,234.5 before, and C and P follow their own
  patterns for the first time. Output changes under those cultures.
- The UTF-8 TryFormat overload is bounded by the destination it is given. It
  formatted through a 366-character buffer of its own and declined anything
  longer, so MaxValue with F300 failed into an 8 KB destination while the char
  overload wrote 379 characters into one the same size.
- ToString no longer caps a format string at 64 KB of output.
- Parsing accepts the same white space as System.Decimal, which is a tab,
  newline, vertical tab, form feed, carriage return or space and nothing else.
  A leading or trailing non-breaking space, and eighteen other characters that
  char.IsWhiteSpace accepts, were consumed before and are refused now. Where
  such a character was also the culture's group separator, a separator
  standing before the first digit was swallowed with it and the value
  accepted; the same narrowing fixes both. Input that parsed before may now be
  refused.
- New: NaN, PositiveInfinity and NegativeInfinity, with IsNaN, IsInfinity,
  IsPositiveInfinity, IsNegativeInfinity and IsFinite beside them. PostgreSQL
  numeric holds all three and the type had no counterpart for any of them.
  Arithmetic propagates them the way System.Double does, but nothing finite
  produces one: division by zero still throws DivideByZeroException and an
  integer part that does not fit still throws OverflowException.
- Equality and ordering now answer NaN three different ways, as the base class
  library does. The == operator is false for two NaNs while Equals is true,
  CompareTo places NaN below every other value so that Array.Sort is well
  defined, and the four relational operators are all false whenever either
  side is NaN. Code that compared values through < or <= sees no change unless
  a NaN reaches it.
- Parsing accepts the culture's NaN and infinity symbols, without regard to
  case and whatever the NumberStyles, and formatting renders a non-finite value
  as that symbol whatever the format string. An unrecognised format specifier
  returns the symbol for these three values where it still throws for every
  other value.
- Converting a non-finite double or float now gives the matching value instead
  of throwing or flattening. CreateChecked returned OverflowException,
  CreateSaturating gave Zero for NaN and MaxValue for an infinity, and the cast
  operator threw; all three now convert. Converting out to decimal, BigInteger
  or an integer type throws under the checked contract and saturates under the
  other two, which is what the base class library does converting a non-finite
  double the same way.
- New: Pow, raising a value to an integer power. It is exact whenever the exact
  power is representable, so 1.05 to the 30th comes back as all 61 of its
  digits, where a multiplication loop written by hand rounds at every step. A
  power that does not fit gives up fractional digits half to even, as a product
  does, and throws only when there are none left; it gives them up once, from
  the exact power, and is reduced into the same 77-digit band as any other
  result that did not fit, for as long as it has fractional digits to give. A
  reduction that reaches scale 0 stops there, so a power with no fraction left
  can still come back at the 78 digits the mantissa holds. A negative exponent
  is the reciprocal, to the precision a division without an explicit scale
  gives, and it answers wherever its own result fits even where the power it
  inverts does not: Pow(2, -300) is a value, though 2 to the 300th is out of
  range.
- Arithmetic, comparison and parsing are faster, by 3% to 25% depending on the
  operation and the width of its operands. Every operation prepared its working
  buffer by zeroing memory the runtime had already zeroed; the largest gains are
  the remainder, the comparison of two values at different scales, and a
  division that comes out exactly. No result changes.
