1.0.0-dev.4
===========

This release adds the Entity Framework Core package for PostgreSQL. One tag
versions every package in the repository, so PetToys.BigDecimal.Core,
PetToys.BigDecimal.Npgsql and PetToys.BigDecimal.ClickHouse are republished as
1.0.0-dev.4 with exactly the public surface they shipped as 1.0.0-dev.3. Only
the new package changed.

PetToys.BigDecimal.Npgsql.EntityFrameworkCore

The Entity Framework Core mapping ships.

Added:
- UseBigDecimal, an extension on NpgsqlDbContextOptionsBuilder, so the
  registration reads UseNpgsql(dataSource, o => o.UseBigDecimal()). A numeric
  column becomes a BigDecimal property, read and written through the handler
  PetToys.BigDecimal.Npgsql installs on the data source. There is no
  ValueConverter anywhere in the path and no value passes through
  System.Decimal.
- The collection forms: BigDecimal[], List<BigDecimal> and their nullable
  element forms map to numeric[]. BigDecimal? needs nothing beyond the
  registration.
- A scale-aware change comparer, without which a property moved from 1.5 to 1.50
  would leave the entity Unchanged and SaveChanges would write nothing.
- HasPrecision reaches both the mapping and the generated schema, and a value
  the declared column cannot hold is refused before it is sent, as an
  OverflowException naming the value and the store type. The property's name is
  read off the DbUpdateException Entity Framework wraps it in; the README shows
  that code.

Notes:
- Registering the mapping does not change what Entity Framework answers by
  default. The store type numeric still maps to System.Decimal, and only a
  property whose CLR type is BigDecimal reaches the new mapping, so scaffolding
  an existing database still produces decimal properties.
- Entity Framework Core 9 and 10 are supported, through
  Npgsql.EntityFrameworkCore.PostgreSQL 9.0.4 up to but not including 11. The
  package ships one assembly compiled against EF Core 9 for every target
  framework, which runs under both majors; an asset compiled against EF Core 10
  cannot be consumed by an application on EF Core 9 at all. Entity Framework
  Core 8 is not supported: its PostgreSQL provider is bound to an internal type
  Npgsql 10 no longer has and throws TypeLoadException at first use.
- A round trip through a faceted column returns the column's scale rather than
  the value's: 1.5 written into a numeric(12,4) reads back as 1.5000. The
  package does not rescale; PostgreSQL applies the column's display scale.
- Queries translate, so comparison, arithmetic and aggregation run on the
  server under the server's rules. PostgreSQL rounds a half away from zero
  where this type rounds half to even, and its division picks its own scale.
  Nothing here reconciles the two.
- The assembly is marked IsAotCompatible, and that is the whole of what it
  claims. Of the four assemblies in this package's graph only Npgsql 10.0.3
  carries IsTrimmable; Entity Framework's own assemblies do not, and an
  assembly attribute cannot vouch for its query pipeline. Unlike the other three
  packages there is no probe behind this marking, because a probe would be
  measuring Entity Framework rather than this repository's code.

1.0.0-dev.3
===========

This release changes how the packages are published rather than what they do.
No public API moves, and no behaviour of any existing operation changes.

All three packages

Added:
- The assemblies are marked IsAotCompatible, which implies IsTrimmable. A
  trimmed or Native AOT publish over them no longer warns that the package has
  not been marked, and the trim, single-file and AOT analyzers now gate every
  build of these projects.

Notes:
- Verified by publishing a probe application over each package and running it,
  trimmed on every supported framework and Native AOT on the newest, rather than
  by a clean analyzer pass. PetToys.BigDecimal.Core and PetToys.BigDecimal.Npgsql
  work in both forms; the Npgsql one uses NpgsqlSlimDataSourceBuilder under
  Native AOT, which UseBigDecimal already overloads.
- PetToys.BigDecimal.ClickHouse is trimmed-only, and the limit is ClickHouse.Driver
  1.4.0 rather than this package. It publishes Native AOT and then throws
  TypeInitializationException on the first query, from a reflective constructor
  lookup in its own type registry. A trimmed publish also warns IL2104 over that
  driver and its Microsoft.IO.RecyclableMemoryStream dependency, neither of which
  is marked trimmable. Both are stated in that package's README.
- Serializing a BigDecimal to JSON in a trimmed or Native AOT application needs a
  source-generated JsonSerializerContext, because both forms turn off the
  reflection-based serializer for every type. The [JsonConverter] attribute the
  type carries is honoured on that path.

1.0.0-dev.2
===========

This release adds the two database integration packages. One tag versions every
package in the repository, so PetToys.BigDecimal.Core is republished as
1.0.0-dev.2 with exactly the public surface it shipped as 1.0.0-dev.1.

PetToys.BigDecimal.Npgsql

The PostgreSQL adapter ships.

Added:
- UseBigDecimal, an extension on NpgsqlDataSourceBuilder,
  NpgsqlSlimDataSourceBuilder and INpgsqlTypeMapper, mapping PostgreSQL numeric
  to BigDecimal and numeric[] to BigDecimal[] through the binary wire format and
  never through System.Decimal. The nullable and List<T> forms come with it, and
  a binary COPY import uses the same mapping.
- GetBigDecimal, GetNullableBigDecimal and their asynchronous forms, on
  NpgsqlDataReader, by ordinal and by column name. A numeric whose integer part
  is larger than BigDecimal can represent throws OverflowException naming the
  column; the same read through GetFieldValue throws the same exception without
  the name, because a converter never learns which column it was handed.
- NaN, Infinity and -Infinity cross as themselves. The infinities need
  PostgreSQL 14 or later, which is where numeric gained them.

Notes:
- Registering the mapping does not change what the driver answers by default. A
  numeric column read with GetValue is still a System.Decimal and GetFieldType
  still reports one, so existing code that does not ask for BigDecimal reads
  exactly what it read before.
- Npgsql 10.0.3 or later is required. The mapping registers through
  Npgsql.Internal, the driver's only extension point for a new type.

PetToys.BigDecimal.ClickHouse

The ClickHouse adapter ships.

Added:
- ClickHouseBigDecimal.CreateQueryOptions, which maps the Decimal32, Decimal64,
  Decimal128 and Decimal256 columns of one query to BigDecimal, and
  UseBigDecimal on ClickHouseClientSettings, which maps every query on a
  connection. Prefer the first: the second changes what GetValue answers for
  every decimal column the connection reads, and it exists because
  ClickHouseCommand has no per-query hook. Nullable and Array columns come with
  either form.
- GetBigDecimal and GetNullableBigDecimal on ClickHouseDataReader, by ordinal
  and by column name. GetFieldValue<BigDecimal> cannot work in any scope,
  because the driver casts its own value to the requested type before consulting
  the hook that would have changed it, and these accessors say so by name.
- InsertBigDecimalAsync on IClickHouseClient, converting every BigDecimal cell
  at its column's scale and width before the driver serialises the batch.
- Writing refuses NaN, Infinity and -Infinity before anything is sent, naming
  the value and the target width. No ClickHouse decimal type represents them.

Notes:
- Reading is total and writing is the direction with a boundary, which is the
  opposite of the PostgreSQL adapter: every ClickHouse decimal fits BigDecimal,
  and every ClickHouse decimal is narrower than it. A value beyond a column's
  precision or width throws OverflowException naming the column and its type.
- Fractional digits beyond a column's scale are rounded half to even by this
  package. ClickHouse itself truncates toward zero when it parses a literal into
  a narrower column, and so does the driver when it lowers a scale; every write
  path here rescales the value first, so neither is ever asked to.
- A round trip returns the column's scale rather than the value's: 1.5 written
  into a Decimal64(4) reads back as 1.5000. ClickHouse keeps the scale in the
  column type and nowhere in the value.
- UseCustomDecimals=true is required on the connection. UseBigDecimal on the
  settings switches it on; the per-query form cannot, and names the option if it
  meets a column the driver decoded through System.Decimal.
- ClickHouse.Driver 1.4.0 or later is required.

1.0.0-dev.1
===========

PetToys.BigDecimal.Core

First prerelease. The core value type is complete and its public surface is
frozen ahead of the database integration packages that follow, so this build
exists to meet a real consumer while the API can still change. The
PetToys.BigDecimal.Npgsql and PetToys.BigDecimal.ClickHouse packages are not
published yet.

Added:
- BigDecimal, a stack-only decimal value type: a 256-bit unsigned magnitude, a
  sign, and a decimal scale of 0 to 255, denoting
  (-1)^sign * magnitude * 10^-scale. Every value of at most 77 significant
  digits is representable, the largest representable magnitude has 78 digits,
  and the range runs from 1e-255 to roughly 1.157e77. That covers every
  ClickHouse Decimal32, Decimal64, Decimal128 and Decimal256 value, and every
  PostgreSQL numeric(p, s) up to 77 digits of precision.
- System.Decimal semantics inside System.Decimal's own domain: trailing zeros
  are preserved by arithmetic and by formatting, equality is numeric so that
  1.0 equals 1.00, and fractional digits that do not fit are rounded to nearest
  with ties to even rather than throwing. The 256-bit magnitude is the only
  hard limit: when a result's significant digits do not fit, the scale is
  reduced as far as needed and OverflowException is reserved for an integer
  part that still does not fit. There is no wrapping mode and no silent
  truncation. Zero is the one deliberate divergence: it never carries a sign.
- Arithmetic: addition, subtraction, multiplication, division, remainder,
  negation and Abs, through both the operators and named methods. Division
  without an explicit scale runs to the full precision the magnitude allows and
  reduces an exact quotient to its shortest scale; an overload takes an explicit
  scale and rounding mode.
- Pow, raising a value to an integer power. It is exact whenever the exact power
  is representable, so 1.05 to the 30th comes back as all 61 of its digits where
  a multiplication loop written by hand rounds at every step. A negative
  exponent is the reciprocal, to the precision a division without an explicit
  scale gives, and it answers wherever its own result fits even where the power
  it inverts does not: Pow(2, -300) is a value, though 2 to the 300th is out of
  range.
- Rounding and scale control: Round, Floor, Ceiling, Truncate, Min, Max and
  Clamp, and WithScale as the widening counterpart to Round. WithScale pads with
  zeros as well as rounding, which is what presenting a value at a column's
  declared scale needs; Round only ever narrows. All five MidpointRounding modes
  are honoured.
- Precision, the number of decimal digits in the unscaled mantissa, so that a
  caller can decide whether a value fits a column before writing it.
- The generic math surface: INumber, ISignedNumber and IMinMaxValue, alongside
  IEquatable, IComparable and the full operator set, so the type drops into code
  written against those constraints. CreateChecked, CreateSaturating and
  CreateTruncating are callable on the type itself and each honours its own
  contract: CreateChecked throws where the value does not fit, the other two
  clamp to the target's range, and all three ask the other type to convert
  itself before giving up with NotSupportedException.
- Conversions to and from every built-in numeric type, plus Int128, UInt128,
  decimal and BigInteger. Conversions from the integer types and from decimal
  are implicit; conversions from double and float, and every conversion out of
  the type, are explicit. Half, NFloat and char are recognised in both
  directions through the generic conversions. Conversion from double and float
  takes the shortest decimal form that round-trips, so (double)(BigDecimal)value
  returns value; this is a deliberate divergence from System.Decimal's own cast,
  which rounds to 15 and 7 significant digits.
- Formatting that matches System.Decimal across its whole surface: the C, E, F,
  G, N, P and R specifiers with an optional precision, custom numeric format
  strings, and the culture's own group size list and negative patterns, so a
  culture that writes (1,234.5) gets that rather than a leading sign. The char
  and UTF-8 TryFormat overloads write the same text and are bounded only by the
  destination the caller passes.
- Parsing through the IParsable, ISpanParsable and IUtf8SpanParsable families,
  honouring NumberStyles in full. The white space accepted is exactly what
  System.Decimal accepts, which is a tab, newline, vertical tab, form feed,
  carriage return or space and nothing else.
- NaN, PositiveInfinity and NegativeInfinity, with IsNaN, IsInfinity,
  IsPositiveInfinity, IsNegativeInfinity and IsFinite beside them. PostgreSQL
  numeric carries all three. Arithmetic propagates them the way System.Double
  does, but nothing finite produces one: division by zero still throws
  DivideByZeroException and an integer part that does not fit still throws
  OverflowException. Equality and ordering answer NaN the three ways the base
  class library does: the == operator is false for two NaNs while Equals is
  true, CompareTo places NaN below every other value so that Array.Sort is well
  defined, and the four relational operators are all false whenever either side
  is NaN. Parsing accepts the culture's NaN and infinity symbols whatever the
  NumberStyles, and formatting renders a non-finite value as that symbol
  whatever the format string.
- A System.Text.Json converter, applied to the type itself so no registration is
  needed. A value is written as a JSON string, which is what preserves digits a
  double reader would lose, and it is supported as a property name as well.
- Zero allocations on every operation without exception, held by a test rather
  than claimed.
- net8.0, net9.0 and net10.0, strong-named and public-signed, with Source Link
  and a symbol package.
